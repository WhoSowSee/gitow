> [!TIP]
> **English version:** [README.md](README.md)

> [!NOTE]
> **gitow - git open web.** Rust CLI для открытия веб-страниц репозитория из текущего рабочего дерева. В её арсенале:
>
> - **Навигация по репозиторию** - Открытие корня репозитория, веток, коммитов, issue, pull request или merge request, истории коммитов, релизов, отслеживаемых файлов и произвольных URL-суффиксов.
> - **Разбор remote** - Поддержка имён remote, прямых remote URL, `insteadOf`-переписываний и алиасов из SSH config.
> - **Ссылки с учётом ветки** - Выбор upstream-ветки, текущей ветки, точного тега или SHA текущего коммита в зависимости от состояния репозитория.
> - **Работа с несколькими remote** - Открытие всех настроенных remote через `--all-remotes`, при этом `origin` идёт первым.
> - **Вывод для скриптов** - Печать URL через `--print` или `BROWSER=echo` без запуска браузера.
> - **Короткая поверхность команд** - Один компактный бинарник `gitow` покрывает все цели навигации.

> [!IMPORTANT]
>
> ## Требования:
>
> - Git
> - Rust 1.88 или новее
> - Системная команда запуска браузера или переменная `BROWSER`

## Установка

### Установка с crates.io

```bash
cargo install gitow
```

Так вы установите последнюю опубликованную версию из crates.io в каталог бинарников Cargo.

### Установка через Nix (Flake)

```bash
nix run github:WhoSowSee/gitow
nix profile install github:WhoSowSee/gitow
```

`nix run` запускает без установки, `nix profile install` устанавливает бинарник в Nix-профиль.

### Установка через Snap (Linux)

Скачайте `.snap`-пакет для своей архитектуры из [GitHub Releases](https://github.com/WhoSowSee/gitow/releases): `amd64` для x86-64 или `arm64` для ARM64.
С установленным `snapd` замените `./gitow.snap` ниже на путь к скачанному файлу:

```bash
sudo snap install --dangerous --classic ./gitow.snap
snap run gitow
```

Флаг `--dangerous` разрешает установку локального пакета без подписи Snap Store; `--classic` нужен для доступа к репозиториям и системному браузеру.
Запускайте `snap run gitow` из каталога Git-репозитория.

### Установка из исходников

```bash
git clone https://github.com/WhoSowSee/gitow.git
cd gitow
cargo install --path .
```

Команда соберёт `gitow`, затем поместит бинарник в каталог Cargo, обычно `~/.cargo/bin`.

### Запуск без установки

```bash
cargo build --release
./target/release/gitow --print
```

Запуск через Cargo:

```bash
cargo run --bin gitow -- --print
```

## Использование

```text
gitow [OPTIONS] [REMOTE_OR_URL] [BRANCH]
```

Примеры:

```bash
gitow
gitow upstream
gitow upstream feature/my-branch
gitow git@github.com:owner/repo.git
gitow https://gitlab.example.com/group/project.git main
gitow --print
```

### Цели навигации

- `-c, --commit` - открыть текущий коммит в интерфейсе forge.
- `-i, --issue` - открыть issue, извлечённую из имени текущей ветки.
- `-m, --pull-requests` - открыть страницу pull request или merge request.
- `-C, --commits` - открыть страницу коммитов выбранной ветки или ref.
- `-r, --releases` - открыть страницу релизов, если forge её поддерживает.
- `-a, --all-remotes` - открыть все настроенные remote.
- `-f, --file <PATH>` - открыть отслеживаемый файл по пути относительно репозитория.
- `-s, --suffix <SUFFIX>` - добавить произвольный суффикс к сгенерированному URL.
- `-p, --print` - напечатать URL вместо запуска браузера.
- `-h, --help` - показать справку.
- `-v, --version` - показать версию программы.

### Частые сценарии

```bash
gitow --commit
gitow --issue
gitow --pull-requests
gitow --commits
gitow --releases
gitow --all-remotes
gitow --file src/main.rs
gitow --suffix actions
gitow --print
```

## Выбор remote и ветки

По умолчанию `gitow` открывает:

1. `open.default.remote`, если он настроен.
2. `origin`, если он настроен.
3. Tracked remote текущей ветки, если он настроен.

Для ref используется upstream-ветка выбранной ветки, если она есть, иначе текущая ветка. В detached `HEAD` утилита сначала пробует точный tag, затем SHA текущего коммита.

## Поддерживаемые remote-репозитории

`gitow` определяет URL-схемы для:

- GitHub
- GitHub Gist
- GitLab.com и self-hosted GitLab
- Gitea, Forgejo, Gogs и Codeberg
- Bitbucket Cloud
- Bitbucket Server / Atlassian Stash
- Azure DevOps / Visual Studio Team Services / Team Foundation Server
- AWS CodeCommit
- generic Git hosting URL

Некоторые страницы зависят от forge. Релизы поддерживаются для GitHub, GitLab и Gitea-совместимых forge. AWS CodeCommit не поддерживает shortcut для issue.

## Конфигурация

`gitow` использует обычную конфигурацию Git. Добавьте `--global`, чтобы применить параметр ко всем репозиториям.

### Remote по умолчанию

Задайте remote, который должен открываться без явного аргумента:

```bash
git config open.default.remote upstream
```

### Пользовательский web-домен и протокол

Если хост Git remote отличается от хоста web UI, настройте URL-matched overrides:

```bash
git config "open.https://git.example.com.domain" "repo.intranet/subpath"
git config "open.https://git.example.com.protocol" "http"
```

Например, remote:

```text
ssh://git@git.example.com:7000/team/repo.git
```

может открываться как:

```text
http://repo.intranet/subpath/team/repo
```

### Gitea, Forgejo и Gogs

Gitea-совместимые forge используют другой формат URL для веток. Codeberg и домены, содержащие `gitea`, `forgejo` или `gogs`, определяются автоматически. Для пользовательских доменов задайте тип forge явно:

```bash
git config "open.https://git.internal.example.forge" "gitea"
```

Значения `gitea`, `forgejo` и `gogs` нормализуются в `gitea`.

### Алиасы SSH config

SCP-style remote могут разрешаться через алиасы SSH config:

```text
Host work
  HostName git.internal.example
```

```bash
git remote set-url origin work:team/repo.git
gitow --print
# печатает https://git.internal.example/team/repo
```

Утилита сначала читает путь из переменной окружения `GITOW_SSH_CONFIG`, затем использует `$HOME/.ssh/config`, если файл существует.

## Выбор браузера и отладка

По умолчанию `gitow` использует системный launcher:

- Windows: `cmd /C start`
- macOS: `open`
- Linux: `xdg-open`
- WSL: Windows PowerShell `Start`

Задайте `BROWSER`, чтобы использовать конкретную команду:

```bash
BROWSER=firefox gitow
```

Используйте `--print` или `BROWSER=echo`, чтобы проверить сгенерированные URL без открытия браузера:

```bash
gitow --print
BROWSER=echo gitow
```
